A

先看结论

有统一契约，功能插件仍随宿主编译

三个内置功能插件遵守相同 Rust 接口。 功能插件清单记录版本、关键词和能力。 清单文件不能加载新的可执行代码。 主题插件使用声明式数据，可以安装主题包。 独立仓库可提供 Rust crate，仍需接入并编译宿主。

B

三个内置插件怎样工作

插件 搜索数据 首屏贡献 默认操作 后台与持久化
备忘录 MemoBook 的只读快照 完整标签命中 粘贴正文 宿主管理工作区的 Markdown 文件
剪贴板历史 ClipboardStore 不参与 粘贴历史内容 宿主启动捕获；SQLite 与附件留在本机
Chrome 书签 BookmarkBook 的只读快照 不参与 在关联用户中打开链接 宿主读取 Bookmarks 并刷新索引

插件负责提供结果。宿主负责排序、选择、预览和执行。 新增能力先在平台适配层实现，再由宿主授权使用。 剪贴板默认关闭。停用后停止搜索与后台捕获。

查询与执行链

标签与关键词同名时，两类结果都保留。 本轮把标签对应的正文放在前面，回车优先粘贴。 Wayland 自动粘贴仍受平台限制，失败时提示手动粘贴。

D

统一规范覆盖了什么

部分 当前约定 边界
插件身份 id、kind、name、version 校验清单；重复 id 保留先注册的实现
版本契约 apiVersion=1、configVersion=1 宿主兼容范围为 >=0.3.0, <0.4.0
查询接口 FeaturePlugin 与 PluginScope 首屏贡献与范围搜索分开
结果规范 SearchItem 来源、匹配分数、预览、默认操作统一
原生权限 capabilities 宿主在平台调用前校验声明
搜索隔离 独立线程、超时、panic 捕获 超时不强制终止线程，也不是安全沙箱
配置 manifest.json 与工作区设置 启用状态可以随配置同步
生命周期 宿主管理后台服务 接口没有通用的 start / stop 钩子
设置界面 宿主的 React 页面 没有第三方 UI 扩展接口
规范不等于第三方运行时

Rust 插件在宿主进程中运行。 当前没有动态加载器、稳定 ABI 或独立插件 SDK。 不要把搜索超时隔离理解成不可信代码隔离。

E

在当前仓库继续扩展

  1. 在 core 的 plugins 目录实现插件。
  2. 在 register_official 中注册它。
  3. 从宿主共享快照读取查询数据。
  4. 让宿主执行带权限的原生操作。
  5. 为新能力实现各平台适配与降级。
  6. 在宿主入口验证查询、操作和启停。
  7. 用浏览器检查界面，并更新 ticket。
  8. 验证后创建中文 Git commit。

需要新结果种类时，扩展宿主模型与界面。 需要后台任务时，明确启动、停止和错误上报。 不要在插件搜索中直接启动后台服务。

F

用独立仓库写插件

维度 当前仓库内实现 独立仓库提供 crate
修改位置 core 与宿主同仓库 插件源码独立；宿主仍需接入
本地联调 直接使用 workspace 通过 Cargo path 依赖
版本固定 跟随宿主提交 宿主用 git rev 固定插件提交
类型兼容 同一份 Rust 类型 需要统一 core 的依赖来源与版本
安装方式 编译宿主 同样编译宿主，没有独立安装入口
原生能力 宿主提供 不能只靠声明创造新能力

建议先用一个小插件验证这条接入路径。 独立仓库工作流目前是可行的源码组织方式。 仓库还没有可直接套用的插件模板或完整接入示例。

G

以后开放独立安装，需要补什么

第三方功能插件生态
  • 稳定 SDK从宿主实现中提取契约与兼容测试
  • 加载运行时选择子进程、WASM 或其他执行边界
  • 权限与资源限制用户授权、文件访问、超时与取消
  • 贡献协议查询、操作、预览、配置与生命周期
  • 包管理安装、更新、版本固定与移除

这部分属于未来架构工作，不是当前已有功能。 应先确认运行边界，再设计分发与安装流程。
