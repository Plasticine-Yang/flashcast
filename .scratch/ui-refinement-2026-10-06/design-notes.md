# 搜索、备忘录与设置精修

## 方向与用户任务

沿用用户已经选定的电弧主题和 03 动作托盘结构，统一界面语法，不重新选择品牌和材质。桌面启动器的主角是搜索结果；备忘录页面的主角是用户正文；设置以当前配置任务为主。采用安静的连续列表、语义蓝色选区、统一 SVG 返回入口和 8px 基础节奏。

既有方向与品类参考沿用 ../product-redesign-2026-10-05/design-notes.md 中的记录。本次以用户截图为问题证据，不新增外部素材或联网设计参考。100% 目标窗口 640×420，窄窗口 480×420，补充 200% 查看与深色、减少动态效果。

## 实现

- 返回：设置和插件页共用 30px 正方形点击区与 20px SVG 箭头，删除文字字符箭头和“搜索”按钮文字。
- 备忘录：新建直接聚焦正文，标签可选；正文首个非空行生成最多 80 字符的列表摘要，空白正文不可保存。旧 Markdown 标题字段保持兼容，保存时由正文生成，无迁移或数据丢弃；旧标题不再作为页面主标题展示。正文预览没有重复标题，编辑、删除始终在内容旁可见。Enter 粘贴及动作菜单仍可使用。
- 设置：顶层组合区块用统一布局控制间距；组内 14px、组间 24px、快捷键区上方 20px 加单一分隔线；正文操作按钮按内容宽度排列。
- Chrome：索引状态与重新读取垂直居中；用户列表紧接状态显示，透明行和上下内边距建立分组；当前用户只显示一个状态标签，企业管理变成辅助信息。路径和实现细节收进可展开来源区。
- 主搜索：移除每行回车图标及底部方向键、Enter、Esc 提示，保留品牌签名与插件次要动作入口。
- 延续短促按下反馈、页面与弹窗进入动效，不在搜索、选中等高频动作引入等待。

## 验证与边界

浏览器使用仓库的模拟宿主，不能证明 Linux 原生材质、全局快捷键或跨应用粘贴。宿主命令与 Markdown 存储格式不变，本次不改 Rust 平台逻辑。

## 验证结果

- `pnpm exec tsc --noEmit` 与 `git diff --check` 通过。仓库未配置 lint 脚本。未运行生产构建和全量测试，未新增 UI 单元测试。
- 浏览器由真实入口走查：创建仅含正文和标签的备忘录；重新编辑读回相同正文；Ctrl+Enter 保存后列表首行摘要随之更新，完整换行保留；取消删除不改变内容，确认删除后数量与当前选择更新。
- 空白正文禁存；表单没有标题输入；关闭弹窗与删除确认后搜索焦点恢复；Ctrl+K 动作菜单、菜单进入删除确认、Escape 返回和方向键仍可使用。主搜索标签结果同样显示正文摘要。
- Chrome 用户关联后当前用户标签更新，重新读取刷新索引；来源折叠区展开后可读取关联用户和完整文件路径。
- 插件快捷键保存后切换页面重读一致；使用与主唤起冲突的 Alt+Space 保存时，错误可见、输入仍保留、当前位置不变。
- 十个设置区块均在 640×420 与 480×420 截图并实际查看，主搜索、备忘录与编辑弹窗也覆盖两种宽度。深色备忘录、深色 Chrome、200% 备忘录和设置局部实际查看完成。截图工具报告没有控制台错误、横向溢出或图片加载失败。
- 弹窗动效留开始／中间／结束三帧，已查看；本机无 ffmpeg，因此没有 MP4。保持已有减少动态效果的 CSS，不新增动效参数；本轮未单独实测系统减少动态效果设置。
- 完成一轮独立存量界面评审，不打分。两项剩余细节已修正并自行复查，详见 visual-review.md。

## 减法与交付边界

删除：每行回车符号、底栏上下键／Enter／Esc 提示、设置返回的“搜索”文字、备忘录重复标题与标题输入、详情粘贴按钮、“新建”前的重复加号、Chrome 的重复已关联／当前使用状态和企业管理边框标签。

保留：正文、标签、用户名称、索引状态、失败原因、完整路径的展开入口，以及实际键盘动作。没有改动宿主命令和旧备忘录存储格式；这轮没有原生 Linux 窗口实测，不能据浏览器截图宣称原生玻璃、物理快捷键与跨应用自动粘贴通过。

## 证据位置

本目录 `reference/` 是用户提供的五张截图；`before-home/`、`before-memo/`、`before-chrome/` 是修改前浏览器基线。`after-home/`、`after-memo/`、`after-editor/`、`after-memo-settings/`、`after-chrome/` 和其余 `after-*/` 保存修改后的 640／480 画面与 report.json。`dark-memo/`、`dark-chrome/` 保存深色；`zoom-memo/`、`zoom-settings/` 保存 200% 图；`editor-motion/` 保存动效帧。所有画面来自浏览器模拟宿主；示例正文、账号、路径都来自仓库现有浏览器数据，未写入用户真实工作区。
