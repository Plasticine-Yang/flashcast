# 全页面控件与状态修正

## 方向

保留电弧的颜色、内容布局与品牌。重点是精致、紧凑、一致的控件语法：薄边界、低对比焦点、可辨认的键盘位置、连续的表单分组。删除框架／浏览器默认装饰和重复状态说明，不改成新的视觉主题。

## 上一轮遗漏

删除确认的两个按钮直接相邻，没有按钮组容器。Chrome 的标题外边距、区块 gap、用户行内边距、content-empty 的 25px padding 叠加；未覆盖单用户缺少书签文件的实际状态。原生数字箭头与复选框没有统一 appearance；粗蓝焦点实际上也包含应用自己设置的 2px outline。

## 本轮实现

- controls.css 集中负责输入、textarea、数字、checkbox、按钮与 summary；移除散落的蓝色 focus 规则。文本控件 32px、按钮 30px，高度不随状态改变。
- 输入焦点用中性细边框和低对比阴影，键盘按钮焦点用 1px 中性 outline。保留焦点可见性与高对比模式支持。
- 移除 WebKit 数字 spinner 与默认 checkbox 外观，保留原生 number 的上下键，范围与整数校验改为页面内错误提示；复选框保留语义和空格操作，绘制统一勾选状态。
- 删除／清空确认独立 flex 按钮组，8px 间距；确认状态有 dialog 语义并锁定 Tab 范围。
- Chrome 用户标题与列表作为一组，删除叠加空状态 padding；空索引短写为“暂无书签”。把常见处理保留为一句，进一步排查按需展开。
- 减少透明度、变更勾选、提交说明、路径、密码、主题包、主快捷键、插件快捷键和备忘录表单都使用同一控件规则；数字、标签等字段的业务逻辑保持原样。
- 增加仅浏览器模拟宿主读取的 scenario 参数，直达 missing、快捷键冲突、备忘录保存错误。真实 Tauri 不读取预览参数，不操作用户真实数据。

## 验收

已完成全部页面盘点、640×420 / 480×420 画面检查、深浅色关键状态、200% 细节和真实浏览器操作。证据与限制见 validation.md，独立盲审与两处追加修正见 visual-review.md。

- 提交说明 textarea 移除浏览器默认拖拽角；凭据输入增加持续可见的字段标签，缩短 placeholder，说明移至已有提示。
- 备忘录失败不再在背景和弹窗重复报错；Error 对象展示 message，宿主原始字符串保持原样。
