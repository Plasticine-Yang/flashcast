# v0.3.6

本次 patch Release 修复 Windows 全局唤起快捷键在后台重新应用配置后失效的问题，并纠正快捷键占用提示。已有快捷键配置继续保留。

## 修复

- 主唤起快捷键统一在 Tauri 主线程注册和更新。文件监听线程只提交请求；迟到请求不能覆盖最新配置，同一生效组合不会重复注册。
- Windows 后端在整个进程内记录所属线程，阻止其它线程创建第二个快捷键隐藏窗口。注销失败会保留原回调并报告错误。
- 更新快捷键时先申请新组合，成功后才释放旧组合。新组合被占用或无效时，旧快捷键及实际生效状态继续保留；插件快捷键也避免对同一组合重复注册。
- Windows 的系统占用错误不再一律显示「已被 Flashcast 注册」。无法确认占用者时明确说明；只有本进程已有成功注册记录才显示自身重复注册。
- 设置和提示区区分正在注册、更新失败及仍然生效的旧绑定；托盘入口继续可用。

## 验证与限制

- 修复前的受控 Windows 系统边界重放能同时复现自身占用提示和唤起回调失效。修复后，相同重复请求、外部占用、无效组合及跨线程注销场景均保留应有的生效状态和回调。
- Windows 原生 API 回归覆盖重复注册、线程归属、独立 HWND 占用、更新失败保留旧回调、成功更新和重复注销；由同 SHA Windows CI 执行。回调检查直接触发句柄，不代表物理按键到 Tauri 窗口的端到端实测。
- 本地完整 Rust 工作区测试、生产前端构建、Linux 原生宿主构建、Windows／macOS 跨目标类型检查、58 项浏览器连续走查、15 项发布入口检查及开发监听隔离检查通过。浏览器使用模拟宿主，不证明原生热键、托盘或自动粘贴行为；没有新增 UI 单元测试。
- Windows 真实桌面上的反复 Alt+Space 唤起、第三方软件冲突解除与端到端自动粘贴仍需实机确认。系统占用提示无法识别具体占用软件，不代表所有第三方冲突已排除。
- Windows 未配置 Authenticode 签名；macOS 使用 ad-hoc 签名、未公证。安装限制沿用 v0.3.5。
