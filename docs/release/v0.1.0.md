# Flashcast v0.1.0

Flashcast 是一个键盘优先的桌面启动器：唤起一个紧凑浮窗，输入软件名即可启动软件，输入插件关键词进入对应搜索范围，输入备忘录标签取回常用内容。

这是首个正式版本。本页的「发布溯源」与「资产与 SHA256」两节由发布流水线在发布时生成，其余内容随仓库中的本文件一同冻结在被打 tag 的提交上。

## 本版本包含

- **启动器**：全局快捷键唤起浮窗、按名称搜索已安装软件、回车启动、稳定排序、异步过期结果丢弃、鼠标不抢键盘选择、中文输入法组合期回车不执行。托盘提供备用入口。
- **备忘录**：带多个标签的文字备忘；首屏输入标签直接命中，可创建、编辑、删除与预览，变更保存在配置工作区并可提交。
- **剪贴板历史**：文字、图片、富文本载荷、文件与视频文件的记录、搜索、预览、置顶、删除、清空、去重与自身写入抑制；可暂停、设置保留期限与容量。
- **Chrome 书签**：选择 Chrome profile，按标题、网址与目录搜索，回车交给该 profile 打开。
- **配置工作区**：选择本地 Git 仓库、初始化新仓库或从远端克隆；设置、插件清单与主题以可读文件保存；变更查看、提交、拉取与推送，脏工作区/分叉/冲突/离线都有明确状态且不强推。
- **主题插件**：浅色、深色与跟随系统，可安装本地主题包并启停；无效主题保留上次可用外观。
- **平台能力报告**：设置页显示系统、架构、Linux 会话类型、快捷键 / 剪贴板 / 自动粘贴的实际支持状态与原因。

## 安装

### Linux x64

- `Flashcast_0.1.0_amd64.AppImage`：`chmod +x` 后直接运行（需要 FUSE；无 FUSE 时用 `--appimage-extract-and-run`）。
- `Flashcast_0.1.0_amd64.deb`：`sudo apt install ./Flashcast_0.1.0_amd64.deb`。

在 Wayland 会话下**没有可用的全局快捷键**（见「已知限制」），请从托盘图标打开。全局快捷键在 X11 会话下可用，但这不能推断 Wayland 下可用。

### Windows x64

- 运行 `Flashcast_0.1.0_x64-setup.exe`，按当前用户安装，不需要管理员权限。

安装程序**未做 Authenticode 签名**（本版本没有可用的代码签名证书），Windows SmartScreen 会提示「Windows 已保护你的电脑」：请点「更多信息」→「仍要运行」。也可以用下面的 SHA256 校验值核对下载内容。

### macOS（Apple Silicon / Intel）

- Apple Silicon 用 `Flashcast_0.1.0_aarch64.dmg`，Intel 用 `Flashcast_0.1.0_x64.dmg`：打开 dmg，把 Flashcast 拖入「应用程序」。

macOS 构建是 **ad-hoc 签名且未公证**，Gatekeeper 会拦截首次启动（提示「无法验证开发者」或「已损坏」）。请任选其一放行：

- 在「应用程序」里右键 Flashcast → 「打开」→ 再点「打开」；
- 或「系统设置 → 隐私与安全性」→ 点「仍要打开」；
- 或 `xattr -dr com.apple.quarantine /Applications/Flashcast.app`。

## 签名状态

| 平台 | 状态 | 说明 |
| --- | --- | --- |
| Linux x64 | 不签名 | AppImage 与 deb 不做代码签名，请用 SHA256 校验值核对 |
| Windows x64 | **未签名** | 没有代码签名证书；SmartScreen 会提示，需要「更多信息 → 仍要运行」 |
| macOS arm64 / x64 | **ad-hoc 签名，未公证** | Gatekeeper 会拦截，需要按上一节手动放行；不是 Developer ID 签名，也没有经过公证 |

有证书时的正式签名与公证分支（Windows 导入 pfx → thumbprint、macOS Developer ID + 公证）在本版本**从未执行过**，因为仓库没有配置相应凭证。上述状态就是本次发布的实际状态，请勿理解为「已签名」或「已公证」。

- **GitHub runner**：Windows 与 macOS runner 上真实执行了系统接口检查（软件发现、进程启动、剪贴板打开、前台窗口读取与恢复、热键注册等）与安装包检查。这些是系统接口层面的证据，**不等于**人工在真实 Windows / macOS 桌面上走完整流程。
- **本机 Linux / Wayland / GNOME 真实桌面**：以下各项**实测通过**——文字、图片、富文本降级与文件列表的剪贴板读取、写入与监听；真实软件发现与回车启动（确有真实进程被拉起）；备忘录标签复制与「已复制，请手动粘贴」降级。
- **编译成功不是行为证据**，替身检查通过也不证明平台适配通过；X11（含 XWayland）下的结果**不能**推断 Wayland 支持。
- 「未覆盖」不等于支持，也不等于不支持，它表示当前环境无法判定；下面逐条列出。

## 已知限制（未覆盖项，不得当作通过）

1. **Linux Wayland 全局快捷键唤起**：未覆盖，能力判定为不支持（Wayland 下没有可用的全局按键抓取接口）。XWayland 下注册成功只记录为 X11 服务器上的成功，没有向真实桌面注入按键验证唤起本身。Wayland 下**托盘是唯一入口**。
2. **唤起前应用身份（focus.capture）**：Wayland 不向普通应用暴露全局焦点窗口，未覆盖；XWayland 下能读到窗口句柄但拿不到应用身份（`id=unknown`）。
3. **Linux Wayland 自动粘贴**：**实测失败**，不是「可能失败」。行为是**复制内容并提示手动粘贴**，不会把内容注入到唤起前的应用。
4. **备忘录粘贴到「唤起前应用」的最终内容**：没有可核对的目标应用，未覆盖（真实剪贴板写入与手动粘贴降级已实测通过）。
5. **剪贴板来源应用推导**：X11 路径需要 xclip，本机未安装；Wayland 没有公开接口，未覆盖。
6. **真实 Tauri webview 的视觉与缩放核对**：未覆盖（本机没有截图与输入注入工具，只有浏览器截图）。
7. **托盘菜单点击**：未覆盖（同上，没有输入注入工具）；只验证过托盘进程能初始化。
8. **Chrome 书签在可见窗口里打开**：未覆盖；真实 Chrome 的启动与页面加载只有 headless 证据（一次性 user-data-dir，不使用用户真实 profile）。
9. **Windows / macOS 真实剪贴板读写**：未覆盖（Windows runner 不执行剪贴板写入；macOS runner 的 HTML/RTF 写入为实测失败，属已记录降级）。
10. **Windows `CF_HDROP` 与 macOS AppleScript 文件列表的真实读写**：未覆盖；Linux 上的 `text/uri-list` 已实测通过。
11. **有证书时的签名 / 公证分支**：从未执行（没有凭证）；当前状态就是上面的 ad-hoc / 未签名。
12. **X11 会话下的剪贴板**：未覆盖（本机是 Wayland 且没有 xclip/xsel），不能用 Wayland 的结果推断 X11 可用。

另外两项平台内降级，不是缺陷隐瞒，实现按此设计：

- **Linux 富文本**：`wl-copy` 一次只能提供一种 MIME 类型，因此恢复富文本时只提供纯文本；富文本载荷仍完整保存在本机历史里。
- **macOS 富文本**：`pbcopy`/`pbpaste` 只支持纯文本，HTML/RTF 既不保存也不恢复。

## 核对下载内容

每个安装包的 SHA256 见下方「资产与 SHA256」一节，也可以直接下载 `SHA256SUMS.txt` 校验：

```sh
# Linux
sha256sum -c SHA256SUMS.txt
# macOS
shasum -a 256 -c SHA256SUMS.txt
```

```powershell
# Windows PowerShell
Get-FileHash .\Flashcast_0.1.0_x64-setup.exe -Algorithm SHA256
# 或
certutil -hashfile Flashcast_0.1.0_x64-setup.exe SHA256
```
