# Flashcast v0.2.0

Flashcast 是一个键盘优先的桌面启动器：唤起一个紧凑浮窗，输入软件名即可启动软件，输入插件关键词进入对应搜索范围，输入备忘录标签取回常用内容。

这一版是**界面版本**：结果列表的排版层级、设置页的信息架构，以及两处键盘 / 焦点缺陷的修复。功能范围与 v0.1.0 相同，平台适配层（`crates/`）没有改动。

本页的「发布溯源」与「资产与 SHA256」两节由发布流水线在发布时生成，其余内容随仓库中的本文件一同冻结在被打 tag 的提交上。

## 本版本包含

### 界面

- **设置页改成左侧分组目录 + 右侧内容区**。10 个区块按使用频率分成 4 组（常用 / 数据与内容 / 配置与同步 / 关于），同一时刻只显示当前区块；`↑↓` 可在目录里移动，切走再回来会回到上次的区块（会话内记忆，重启回到「全局快捷键」）。改前 10 个区块平铺在一个滚动列里：真实窗口 640×420 下内容总高 3837px、可视区 363px，等于要滚 10.57 屏，而且低频运维排在最前面；改后目录 10 个区块一屏内全部可见。
- **提示条移到窗口顶部常驻可见**。它原来在整个设置页的最底部，在靠前的区块里操作完，反馈其实在视口外。
- **结果列表采用更舒展的排版**：行高 48px、行距 4px、图标 30px、圆角 10px，标题 15px/500 并收紧字距。代价如实写出：固定窗口下首屏完整可见条目由 7 条变为 6 条（列表区约 325px）。
- **搜索框的行内焦点蓝框改为窗口表达**（强调色外框 + 光环），设置页各控件的键盘焦点环不变。
- **设置页不再显示顶部搜索行**（进入设置页时隐藏）：它在设置页里不是搜索表面，且目录需要这点高度。

### 修复

- **唤起后搜索框自动获得焦点**。此前输入框的 ref 从未绑定，`focusInput()` 一直在对空引用调用 `focus()`：唤起后必须先用鼠标点一下搜索框才能打字，「窗口打开后立即输入查询」实际没有实现。
- **鼠标点过结果行之后键盘不再失效**。键盘入口原本只绑在搜索输入框上，点过任何一行后焦点落到 `body`，`↑↓` 选择、`Enter` 执行、`Escape` 关闭会一起失效；现在与设置页的既有做法一致，挂在 `window` 上（保留中文输入法组合守卫，并避开按钮上的原生回车）。

## 安装

### Linux x64

- `Flashcast_0.2.0_amd64.AppImage`：`chmod +x` 后直接运行（需要 FUSE；无 FUSE 时用 `--appimage-extract-and-run`）。
- `Flashcast_0.2.0_amd64.deb`：`sudo apt install ./Flashcast_0.2.0_amd64.deb`。

在 Wayland 会话下**没有可用的全局快捷键**（见「已知限制」），请从托盘图标打开。全局快捷键在 X11 会话下可用，但这不能推断 Wayland 下可用。

### Windows x64

- 运行 `Flashcast_0.2.0_x64-setup.exe`，按当前用户安装，不需要管理员权限。

安装程序**未做 Authenticode 签名**（本版本没有可用的代码签名证书），Windows SmartScreen 会提示「Windows 已保护你的电脑」：请点「更多信息」→「仍要运行」。也可以用下面的 SHA256 校验值核对下载内容。

### macOS（Apple Silicon / Intel）

- Apple Silicon 用 `Flashcast_0.2.0_aarch64.dmg`，Intel 用 `Flashcast_0.2.0_x64.dmg`：打开 dmg，把 Flashcast 拖入「应用程序」。

macOS 构建是 **ad-hoc 签名且未公证**，Gatekeeper 会拦截首次启动（提示「无法验证开发者」或「已损坏」）。请任选其一放行：

- 在「应用程序」里右键 Flashcast → 「打开」→ 再点「打开」；
- 或「系统设置 → 隐私与安全性」→ 点「仍要打开」；
- 或 `xattr -dr com.apple.quarantine /Applications/Flashcast.app`。

## 签名状态

| 平台 | 状态 | 说明 |
| --- | --- | --- |
| Linux x64 | 不签名 | AppImage 与 deb 不做代码签名，请用 SHA256 校验值核对 |
| Windows x64 | **未签名** | 没有代码签名证书；SmartScreen 会提示，需要「更多信息 → 仍要运行」 |

有证书时的正式签名与公证分支（Windows 导入 pfx → thumbprint、macOS Developer ID + 公证）**从未执行过**，因为仓库没有配置相应凭证。上述状态就是本次发布的实际状态，请勿理解为「已签名」或「已公证」。

## 平台验证范围

**本版的平台证据沿用 v0.1.0，没有在 v0.2.0 上重新做过真实 Windows / macOS 桌面验证。** 原因是本版只改前端与版本元数据：`crates/`（平台适配层）与 `scripts/ci/` 的实现自 v0.1.0（`c1cf492`）起没有改动。下面的数字与逐条限制来自 v0.1.0 的能力报告，按原样引用，未重新采集。

完整的逐项记录见 [docs/platform/capability-report.md](https://github.com/Plasticine-Yang/flashcast/blob/v0.1.0/docs/platform/capability-report.md)（机器可读版本是同一提交里的 `capability-report.json`；证据采集于 CI 运行 [36861987134](https://github.com/Plasticine-Yang/flashcast/actions/runs/36861987134)）。摘要：

| 类别 | 实测通过 | 实测失败 | 未覆盖 |
| --- | --- | --- | --- |
| 真实平台 / 真实桌面检查 | 49 | 5 | 25 |
| 替身检查（经宿主入口的 `cargo test`） | 15 组，共 362 项 | 0 | 0 |
| 未覆盖条目（逐条原因） | — | — | 12 |

- **GitHub runner**：Windows 与 macOS runner 上真实执行了系统接口检查（软件发现、进程启动、剪贴板打开、前台窗口读取与恢复、热键注册等）与安装包检查。这些是系统接口层面的证据，**不等于**人工在真实 Windows / macOS 桌面上走完整流程。
- **本机 Linux / Wayland / GNOME 真实桌面**：以下各项**实测通过**——文字、图片、富文本降级与文件列表的剪贴板读取、写入与监听；真实软件发现与回车启动（确有真实进程被拉起）；备忘录标签复制与「已复制，请手动粘贴」降级。
- **本次 tag 的 CI 重跑范围**：三平台 runner 上重跑平台接口检查，并为每个安装包现场生成检查报告（`version` 与 `commit` 由发布脚本强制核对，旧提交或旧版本的产物会被拒绝发布）。这仍属系统接口与打包层面的证据，不改变上一段的结论。
- **编译成功不是行为证据**，替身检查通过也不证明平台适配通过；X11（含 XWayland）下的结果**不能**推断 Wayland 支持。
- 「未覆盖」不等于支持，也不等于不支持，它表示当前环境无法判定；下面逐条列出。

## 已知限制（未覆盖项，不得当作通过）

以下 12 条来自 v0.1.0 的能力报告。平台适配层未改动，因此这些限制对本版同样适用；**本版没有重新验证它们**。

1. **Linux Wayland 全局快捷键唤起**：未覆盖，能力判定为不支持（Wayland 下没有可用的全局按键抓取接口）。XWayland 下注册成功只记录为 X11 服务器上的成功，没有向真实桌面注入按键验证唤起本身。Wayland 下**托盘是唯一入口**。
2. **唤起前应用身份（focus.capture）**：Wayland 不向普通应用暴露全局焦点窗口，未覆盖；XWayland 下能读到窗口句柄但拿不到应用身份（`id=unknown`）。
3. **自动粘贴的端到端验证**：Linux Wayland 下**实测失败**，不是「可能失败」——行为是**复制内容并提示手动粘贴**，不会把内容注入到唤起前的应用；Windows / macOS runner 上只验证了注入后端与权限前置条件（`paste.prepare`），**刻意没有注入真实按键**，所以真实桌面上的端到端粘贴同样是未覆盖。
4. **备忘录粘贴到「唤起前应用」的最终内容**：没有可核对的目标应用，未覆盖（真实剪贴板写入与手动粘贴降级已实测通过）。
5. **剪贴板来源应用推导**：X11 路径需要 xclip，本机未安装；Wayland 没有公开接口，未覆盖。
6. **真实 Tauri webview 的视觉与缩放核对**：未覆盖（本机没有截图与输入注入工具，只有浏览器截图）。本版的界面改动同样只有浏览器截图与浏览器交互检查（`pnpm ui-check`），**没有在真实 Tauri webview 上核对过视觉**。
7. **托盘菜单点击**：未覆盖（同上，没有输入注入工具）；只验证过托盘进程能初始化。
8. **Chrome 书签在可见窗口里打开**：未覆盖；真实 Chrome 的启动与页面加载只有 headless 证据（一次性 user-data-dir，不使用用户真实 profile）。
9. **Windows / macOS 真实剪贴板读写**：未覆盖（Windows runner 不执行剪贴板写入；macOS runner 的 HTML/RTF 写入为实测失败，属已记录降级）。
10. **Windows `CF_HDROP` 与 macOS AppleScript 文件列表的真实读写**：未覆盖；Linux 上的 `text/uri-list` 已实测通过。
11. **有证书时的签名 / 公证分支**：从未执行（没有凭证）；当前状态就是上面的 ad-hoc / 未签名。
12. **X11 会话下的剪贴板**：未覆盖（本机是 Wayland 且没有 xclip/xsel），不能用 Wayland 的结果推断 X11 可用。

另外两项平台内降级，不是缺陷隐瞒，实现按此设计：

- **Linux 富文本**：`wl-copy` 一次只能提供一种 MIME 类型，因此恢复富文本时只提供纯文本；富文本载荷仍完整保存在本机历史里。
- **macOS 富文本**：`pbcopy`/`pbpaste` 只支持纯文本，HTML/RTF 既不保存也不恢复。

每个安装包的 SHA256 见下方「资产与 SHA256」一节，也可以直接下载 `SHA256SUMS.txt` 校验：

```sh
# Linux
sha256sum -c SHA256SUMS.txt

shasum -a 256 -c SHA256SUMS.txt
```

```powershell
# Windows PowerShell
Get-FileHash .\Flashcast_0.2.0_x64-setup.exe -Algorithm SHA256
# 或
certutil -hashfile Flashcast_0.2.0_x64-setup.exe SHA256
```
